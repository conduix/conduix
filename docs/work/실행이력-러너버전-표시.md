# 작업 지시 — 모든 실행을 최신 빌드로 돌리고, 버전을 이력에 남긴다

작성 2026-09-10 / 상태: 미착수

## 한 줄 요약

**최신 빌드가 있는데도 일부 실행이 `latest` 이미지의 낡은 기본 바이너리로 돈다.**
그 사실이 이력에도 안 남아 GUI 의 Runner Version 이 공란이다.

빌드된 바이너리를 놔두고 `latest` 를 실행에 쓰는 것 자체가 잘못이다.
버전 표시는 그 결과로 따라오는 문제다.

## 재현

1. 커스텀 native stage 를 쓰지 않는 워크플로를 실행한다
   (예: `[batch] 아동복지급식 가맹점 → MySQL`)
2. GUI 워크플로 상세 → **Runner Version 이 비어 있다**

실측: `workflow_executions` 50건 중 **4건만** `runner_version_id` 가 채워짐 (8%)

---

## 원인

### 리졸버가 커스텀 stage 없는 워크플로를 빌드 대상에서 제외한다

`control-plane/internal/services/runner_resolver.go:158`

```go
func (r *RunnerResolver) ResolveRunnerVersion(workflow *models.Workflow) (string, string, bool, error) {
    nativePlugins, err := r.findNativePluginsInWorkflow(workflow)
    ...
    if len(nativePlugins) == 0 {
        return "", DefaultRunnerImage, false, nil
        //      ↑ 버전 ID 는 빈 문자열, 이미지만 반환
    }
    ...
}
```

| 실행 형태 | 실제 실행 대상 | 이력 기록 |
|---|---|---|
| 커스텀 stage 있음 | 최신 ready 바이너리 (initContainer 주입) | `runner_version_id` ✅ |
| **커스텀 stage 없음** | **`latest` 이미지에 든 기본 바이너리** | **아무것도 없음** ❌ |

후자는 **최신 빌드를 놔두고 낡은 바이너리로 도는 것**이다. 코어(pipeline-core /
shared / plugin-sdk)를 고쳐 재빌드해도 이 경로의 워크플로에는 영영 반영되지 않는다.

### 반환된 이미지를 모든 호출부가 버린다

```go
versionID, _, _, rerr := h.runnerResolver.ResolveRunnerVersion(&workflow)
//          ↑ DefaultRunnerImage 가 여기서 사라진다
```

호출부 6곳 전부 두 번째 반환값을 `_` 로 받는다:

```
control-plane/internal/api/handlers/workflow_start.go:76
control-plane/internal/api/handlers/workflow.go:797, 887, 965
control-plane/internal/services/scheduler_service.go:459, 530
```

### 저장할 자리도 없다

- `models.WorkflowExecution` — `RunnerVersionID` 만 있고 이미지 필드가 없다
- `pipeline_runs.runner_image` — 컬럼은 있으나 **테이블 행이 0건** (안 쓰이는 경로로 보임)

### `latest` 는 추적에 쓸 수 없다

태그가 가리키는 다이제스트는 계속 바뀐다. `latest` 라고만 남겨도
"그때 무슨 바이너리였는지" 는 알 수 없다. **다이제스트가 필요하다.**

## 참고 — 오해하기 쉬운 지점 두 가지

조사 중 확인한 사실이다. 이 작업의 전제이므로 적어둔다.

**① 빌드는 워크플로별로 하지 않는다**

`runner_builder.go:185`
```go
rb.db.Where("type = ? AND status = ?", "native", "active").Find(&plugins)
```
활성 native plugin **전부**를 한 바이너리로 컴파일한다.
실측: 빌드 18회, 모두 같은 플러그인 1개(`geocode_kakao`)를 담고 있다.

**② `latest` 는 두 역할을 겸하고 있다 — 분리해야 한다**

| 역할 | 판정 |
|---|---|
| **실행 대상** (커스텀 없는 워크플로의 바이너리) | ❌ **잘못. 최신 ready 바이너리로 대체해야 한다** |
| **베이스 컨테이너** (initContainer 가 바이너리를 내려놓을 껍데기) | 이미지 자체는 필요 |

커스텀 바이너리는 initContainer 가 `/runner` 에 내려놓는다
(`pipeline-worker/internal/k8s/job_manager.go:394`).

```go
func (m *JobManager) injectRunnerBinary(ps *corev1.PodSpec, runnerVersionID, image string, ...) {
    if runnerVersionID == "" {
        return   // 주입 생략 → 이미지의 기본 바이너리로 실행
    }
    ...
}
```

파드 이미지가 `latest` 로 **표시되는 것**은 베이스라서 그렇다.
문제는 `runnerVersionID == ""` 일 때 **주입을 건너뛰어 그 이미지에 든 낡은
기본 바이너리로 실행된다**는 점이다. 최신 빌드가 ready 로 있는데도 그렇다.

## 해야 할 것

### 핵심 — 커스텀 stage 유무와 무관하게 최신 ready 바이너리로 실행

`runner_resolver.go:157` 의 조기 반환을 제거한다.

```go
// 제거 대상
if len(nativePlugins) == 0 {
    return "", DefaultRunnerImage, false, nil
}
```

이 한 줄만 빼면 **아래 검증이 모든 워크플로에 그대로 적용된다** — 이미 구현돼 있다:

| 검증 | 동작 |
|---|---|
| pending plugin 있음 | `BuildRequiredError(PluginChanged)` |
| ready 버전 없음 | `BuildRequiredError(NoReadyVersion)` |
| ready 인데 `BinarySize == 0` | `BuildRequiredError(BinaryMissing)` |
| 코어 소스가 바뀜 | `BuildRequiredError(CoreChanged)` |
| 통과 | `latestReady.ID`, `latestReady.ImageTag` |

`nativePlugins` 는 이제 **빌드 필요 판정에만** 쓰인다(어떤 플러그인이 pending 인지).
실행 대상 선택에는 관여하지 않는다.

**결정 필요 — ready 버전이 하나도 없는 초기 상태**

지금은 커스텀 stage 없는 워크플로가 이미지로라도 돌지만, 위 변경 후에는
`BuildReasonNoReadyVersion` 으로 막힌다. 두 선택지가 있다:

- **(a) 빌드를 요구한다** — 일관되지만, 커스텀 stage 를 아예 안 쓰는 사용자도
  최초 1회 빌드를 해야 한다
- **(b) 그때만 이미지 폴백** — 편하지만 "낡은 바이너리로 도는" 경로가 남는다.
  둔다면 **반드시 이미지+다이제스트를 이력에 기록**해야 한다

권고는 (a) 다. 빌드는 플러그인 유무와 무관하게 코어 변경도 반영하므로,
"빌드 없이 도는 실행" 을 없애는 편이 추적·재현에 일관적이다.

### 따라오는 것 — 이력 기록

위를 고치면 `runner_version_id` 는 항상 채워진다. 남는 일은:

1. 호출부 6곳에서 두 번째 반환값(이미지)도 받아 저장
   - (b) 를 택했다면 필수. (a) 라면 관측용
2. `models.WorkflowExecution` 에 `RunnerImage string` 추가 + 마이그레이션
   (현재 최신 `000008`, → `000009_add_execution_runner_image`)
3. `RunnerDeploymentRow` 에 `runner_image` 추가 → GUI 표시

### 이미지로 실행되는 경로가 남는다면

**태그가 아니라 다이제스트를 기록한다.** `latest` 는 가리키는 대상이 계속 바뀌어
"그때 무엇이 돌았는지" 를 말해주지 못한다. `runner_versions.image_digest` 컬럼이
이미 있으니 같은 방식으로 둔다.

## 완료 기준

- [ ] **커스텀 stage 를 쓰지 않는 워크플로도 최신 ready 바이너리로 실행된다**
- [ ] `latest` 이미지의 기본 바이너리로 실행되는 경로가 없다 (또는 남긴다면 이력에 다이제스트가 남는다)
- [ ] `workflow_executions.runner_version_id` 누락이 0 이 된다 (현재 92% 누락)
- [ ] GUI 에 실행 대상 버전이 표시된다
- [ ] `[batch] 아동복지급식 가맹점 → MySQL` 로 실제 확인 — 실행 후
      `kubectl get pod <job-pod> -o jsonpath='{.spec.initContainers[*].name}'` 에
      `fetch-runner` 가 있어야 한다
