## 1~10. 점 데이터 — 가져올 항목

공통으로 **이름 · 주소 · 좌표**를 뽑고, 나머지는 서비스에 쓰는 속성만 가져온다.

### 1. 공중화장실 (15155058) — ✅ 2026-09-03 실호출로 34개 필드 전체 확정

기존 후보였던 전국공중화장실표준데이터(15012892) 대신 **행정안전부_공중화장실정보
조회서비스(15155058)** 로 확정. 총 53,572건 (2026-09-03 기준).

**API**
- 엔드포인트: `https://apis.data.go.kr/1741000/public_restroom_info_v2`
- 오퍼레이션: `info_v2` (현재 상태), `history_v2` (과거 시점 스냅샷 — 아래)
- 파라미터: `serviceKey` · `pageNo` · `numOfRows` · `returnType`(json/xml)
- 인증키: 루트 `.env` 의 `DATA_GO_KR_SERVICE_KEY` (**repo 가 public — 문서·코드에 키 기록 금지**), 활용기간 2026-09-03 ~ 2028-09-03
- 증분 수집용 필터 제공: `cond[DAT_UPDT_PNT::GTE/LT]` · `cond[LAST_MDFCN_PNT::GTE/LT]` · `cond[DAT_CRTR_YMD::GTE/LT]` · `cond[OPN_ATMY_GRP_CD::EQ]` · `cond[LCTN_ROAD_NM_ADDR::LIKE]`
- 트래픽: 개발계정 일 10,000 — **호출 횟수 기준** (에러코드 22 "일일 호출 허용량", -10 "허용 횟수"). 단 초당 요청 제한 있음(에러 23).
- **수집 파라미터 확정: `numOfRows=2000`, 순차 호출 + 호출 간 간격** → 전체 수집 27회
  (53,572÷2,000). 5,000도 실측으론 동작하지만 서버 부담·타임아웃 여유를 두고 2,000 로 결정.

**갱신 특성 — realtime 소스가 아니다** (2026-09-03 실측)
- 제공처 명시: 매일 갱신, **2일 전 기준 현행화**. 실측으로도 갱신분(`DAT_UPDT_PNT`)이
  **매일 밤 21~22시경 하루 한 번의 배치**로만 찍힌다 (21:27/21:57/22:27 클러스터).
- 변경량 자체가 극소: 최근 6일간 갱신 6건, 9/1 이후 3건 (전체 53,572건 대비).
- `history_v2` 는 이벤트 스트림이 아니라 **BASE_DATE 시점 상태를 재구성해 주는
  point-in-time 스냅샷 조회**다 ("입력한 데이터기준일자 기준으로 과거시점에 개방되었던
  데이터"). 게다가 `cond[BASE_DATE::EQ]` 와 `cond[OPN_ATMY_GRP_CD::EQ]`(자치단체코드)가
  **둘 다 필수**라 전국을 한 번에 못 읽는다 — 실시간성과 무관한 감사/이력용.
  ⚠️ 실측 중 스냅샷 건수(268)와 info_v2 현재 건수(282)가 안 맞는 사례 관측 — 정합성 미확인.
- → **파이프라인 결론**: 원천이 일배치이므로 realtime(CDC) 수집은 이 API 에 성립하지
  않는다. `info_v2` + `DAT_UPDT_PNT::GTE` 체크포인트 기반 **증분 배치(일 1회, 밤 배치
  이후 시각)** 가 적정. 전체 재수집은 정합성 리셋용으로 가끔만. CDC/realtime 은 수집
  이후 우리 저장소 → 서비스 전파 단계에서만 의미가 있다.

**가져올 항목** (영문 필드명 = 실응답 확인값)
```
RSTRM_NM(화장실명) · SE_NM(구분명: 공중/개방화장실) · LCTN_ROAD_NM_ADDR(도로명주소) · LCTN_LOTNO_ADDR(지번주소)

```
나머지 필드: BSS_STT_NM · RSTRM_PSN_SE_NM(소유구분) · WSTE_PRCS_MTH_NM(오물처리방식) ·
SFTY_MNG_FCLT_INSTL_TRGT · INSTL_YM · RMOD_YM — 서비스에 불필요하면 제외.

⚠️ **좌표를 주지 않는다** (34개 필드에 위경도 없음, 실응답으로 확인). 주소로 지오코딩해야 한다.
⚠️ **`BSS_STT_NM` 은 영업상태가 아니라 근거법령명이다.** 이름에 속지 말 것. 이 API 응답에는 영업상태 필드 자체가 없다.
⚠️ `DAT_UPDT_SE`(데이터갱신구분): `I` · `U` 관측 확인 (등록/수정). `D`(삭제)는 미관측 —
삭제가 D 레코드로 오는지, 목록에서 그냥 빠지는지 미확인. 증분만으로는 삭제를 못 잡는다.

**삭제 반영 설계 (확정, Conduix 구현 완료) — 전체 재수집 시 mark-and-sweep**

SQL sink 옵션으로 구현됨 (완전 opt-in — 미설정 파이프라인은 무영향). 운영툴 UI 지원.
```yaml
outputs:
  - type: sql
    config:
      upsert: true
      synced_at_column: synced_at   # 매 upsert 에 시작시각 T 스탬프
      sweep:                        # 생략 시 sweep 안 함 (삭제 없는 배치 수집)
        mode: delete                # delete(물리) | soft(deleted_at 플래그, 재등장 시 NULL 복원)
```
```
① 전체 수집 시작 전 시각 T 기록
② 재수집: 응답 전 레코드를 추가/업데이트 (우리 DB 의 synced_at 을 매번 갱신)
③ 27회 전부 성공하면: synced_at < T 인 레코드 = 이번 응답에 없었던 것 → 삭제 대상
```
- 판정 기준은 API 의 DAT_UPDT_PNT 가 아니라 **우리 DB 의 synced_at** 이다.
  (API 갱신시점은 원본 변경 시각일 뿐, "이번 수집에 나타났는가" 와 무관)
- ⚠️ **부분 실패 시 sweep 금지**: 27회 중 일부만 성공한 채 삭제 판정하면
  못 받은 페이지의 레코드가 전부 오탐 삭제된다. 전 페이지 성공이 sweep 의 전제조건.

**참고 코드표** (`~/Downloads/개방자치단체코드_영업상태코드_행정체제개편반영_20260702.xlsx`)
- 시트1 개방자치단체코드: 294건. `_ALL` 접미사는 광역 전체 코드. **2026-07-01 행정체제개편(전남광주통합특별시 신설 등) 변경 67건 포함** — 구 전라남도(6460000)·광주광역시(6290000) 코드는 삭제됨. 예: 응답의 5805000 = 전남광주동구(신규).
- 시트2 영업상태코드: 01 영업/정상 · 02 휴업 · 03 폐업 · 04 취소/말소/만료/정지/중지 · 05 제외/삭제/전출 · 06 기타. (이 API 에는 해당 필드 없음 — 다른 행안부 개방 API 용)

## 11. 침수우려지역 — 데이터셋 미특정

**가져오는 것은 지명·지구명·주소 텍스트다. 폴리곤이 아니다.**

- 정밀한 침수 실측 영역(침수흔적도)이 공개 API로 제공되는지는 **확인하지 못했다.**
  전제로 삼지 않는다.
- 실제로 기대할 수 있는 형태는 **침수우려 지구·지역의 이름 목록**이다.
  (예: "○○동 △△지구")

**폴리곤은 수집물이 아니라 파생물이다**
```
받아오는 것:  지명 / 지구명 / 주소  (텍스트)
        ↓     행정경계 데이터와 조인
만드는 것:    폴리곤
```

**따라서 정확도는 원본 지명의 단위에 묶인다.**
동 단위 지명이면 **동 전체가 칠해진다.** 실제 침수 구간은 그 안의 일부일 뿐이다.
"이 지점이 침수 구역 안"이라고 단정할 수 없고, "이 동네가 침수우려 지역으로
지정되어 있다" 수준까지만 말할 수 있다. 안내 문구도 거기에 맞춰야 한다.

**확정 전 필요한 것**
- 어느 데이터셋이 이 지명 목록을 주는지 특정
- 지명의 단위 (동 / 지구 / 도로구간)
- 조인에 쓸 행정경계 데이터 확보

## 수집하지 않는 것

### 기상특보 (기상청) — MCP 조회

**저장하지 않는다.** 특보는 발효·해제되는 실시간 상태라, 수집해 저장하는 순간
낡은 값이 된다. 해제된 특보를 띄우는 것은 안 띄우느니만 못하다.

| | 수집·저장 | MCP 조회 (선택) |
|---|---|---|
| 최신성 | 수집 주기만큼 뒤처짐 | 물어보는 시점의 상태 |
| 해제 반영 | 다음 수집까지 지연 | 즉시 |
| 저장소 | 갱신·만료 관리 필요 | 불필요 |

→ 파이프라인 대상이 아니다. 서비스가 필요할 때 호출한다.
